## Fixed rounds

### Round r15 — SCP record modes carried client-controlled special FileMode bits (r15)
- Location: internal/protocol/sftp/scp.go — `parseSCPRecord` (mode field); consumers at the sink's `fsys.Open` (`:438`) and `Mkdir` (`:416`).
- Root cause: the octal mode from a C/D record was returned unmasked (`uint32(m)`). Real scp clients send 4-digit octal (≤ `0o7777`), but crafted values `0o40000000`/`0o20000000`/`0o10000000` parse cleanly through `ParseUint(parts[0], 8, 32)` and land exactly on Go's special `FileMode` bits (`ModeSetuid`/`ModeSetgid`/`ModeSocket`), which the sink passed verbatim into the backend. A privileged local deployment (CAP_FSETID, e.g. a root service) plants setuid/setgid files on disk; the memory backend persists the `FileMode` verbatim (proven: `u---------` stored). Contract basis: the repo's own SFTP SETSTAT masking (`&0o7777`), OpenSSH's permission-bits-only create semantics, and Go's `FileMode` layout — the crafted digits are outside the scp mode grammar entirely. Distinct from round-24 (uncapped `ReadString`; fixed earlier) — same file, different root cause.
- Investigation nuance: Linux `write()` strips S_ISUID when the writer lacks CAP_FSETID, so every sink-driven `Stat` probe in this unprivileged container masked the local-backend symptom while direct-open probes kept the bit. Five targeted probes localized the contradiction; the deterministic proof therefore asserts at the `Open` seam (a recording `vfs` wrapper captures the mode the sink hands the backend) plus memory-backend storage.
- Proof (before): `TestR15SinkMasksSpecialModeBits` via `go test -overlay .temp_files/proof-driven-bug-hunter/r15-20261022-scp-deep-a4e9/overlay.json -run TestR15 -count=1 -v ./internal/protocol/sftp/` — exit 1, six subtests red (`sink passed client-controlled bits beyond the permission bits … perm=40000000 (mode u---------)`, setgid `g---------` and socket likewise; memory legs `persisted client-supplied bits beyond permissions`), the `C0644` control green. Post-fix: exit 0. Scratch removed after the round.
- Patch: `m &= 0o777` in `parseSCPRecord` with an explanatory comment. `C0644` passes through unchanged; `C4755` → `0755`. Commit `f048da0`.
- Regression tests: `TestSCPSinkModeIsPermissionBitsOnly` (internal/protocol/sftp/scp_test.go) — parse table (three crafted values + the classic `C4755` form), the `C0644` control, and a sink-level memory assertion; seen red against an isolated copy of the unfixed `scp.go` via `go -overlay` (shared files never reverted), green in-tree.
- Gates: focused sftp suite ok; `gofmt`/`go vet` clean; full suite 28 packages ok; race gate clean.
